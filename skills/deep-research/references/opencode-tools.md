# Running this skill on a harness that is not Claude Code

`research next` prints a dispatch packet naming Claude Code's concepts —
an agent file, a model, an output path. That text is generated by
`scheduler.render()` from `run.yaml`, and it is deliberately **not**
harness-aware: it is one of the most heavily tested functions here, and
its exact shape is pinned. So the packet does not change per harness;
this page tells you how to read it.

## Reading the dispatch packet

| The packet says | What to do under opencode |
|---|---|
| `agent <path>` | Read that file. Its body is the subagent's instructions; its frontmatter names the tools that subagent needs. |
| `model <name>` | Advisory. These are Claude model names — `haiku` for cheap mechanical work, `sonnet` for judgement. Use the nearest equivalent you have. |
| `input {...}` | Pass this JSON to the subagent verbatim. It is the whole of what that agent may see. |
| `schema <path>` | The contract its output must satisfy. `submit` validates against it and rejects on failure. |
| `write <path>` | Where the subagent writes its JSON artifact. |
| "Dispatch these IN PARALLEL, in one message" | One `task` call per dispatch, all in a single message, `subagent_type: "general"`. |

## Tool names in the agent files

| An agent's frontmatter says | Under opencode |
|---|---|
| `WebSearch` | `websearch` |
| `WebFetch` | `webfetch` |
| `tools: []` | no tools — and this matters. Five of the eight agents are deliberately tool-less, which is what makes their isolation a security property and not just a context one. Do not grant tools an agent does not ask for. |

## Everything else

| The skill says | Under opencode |
|---|---|
| `uv run …/research.py …` | `bash` |
| Read a file | `read` |
| Create, edit or delete a file | `edit`, `write` |
| Search files | `grep`, `glob` |

## What is not verified

This mapping is written from opencode's documented tool names. **No part of
the research loop has been executed under opencode.** The plugin's `config`
hook registers this package's `skills/` directory — checked by running the
shim under Node — but nobody has watched opencode load a skill from it, and
whether the loop's parallel dispatch behaves equivalently is untested. If you
are the first to run it, treat surprises as expected and please report them.
